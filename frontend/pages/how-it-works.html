ProofDrop / How it works

What "sealed" means in v1

ProofDrop starts by proving file integrity locally: hash the file, save a portable proof record, and verify the same bytes later. The blockchain anchor is the next layer.

STEP 01 / DROP

The file is fingerprinted, not uploaded

When you drop a file into ProofDrop, it is hashed right in your browser using SHA-256. That one-way function turns the file into a fixed fingerprint. Change a single byte and the fingerprint changes.

  • The file itself never leaves your device.
  • ProofDrop does not need to store the original file.
  • You can re-run the hash later and confirm it matches.
STEP 02 / SAVE

The local proof record is created

The seal page saves the filename, size, SHA-256 fingerprint, and timestamp into a small JSON proof record. For now, this is a local preview of the full blockchain flow.

  • The downloaded proof record is portable.
  • It does not contain the actual file.
  • The next v1 milestone is recording the fingerprint on Sepolia through MetaMask.
STEP 03 / VERIFY

Anyone can check whether the file still matches

Verification takes the original file and the proof record, recomputes the file fingerprint locally, and compares the two hashes. If they match, the file bytes are unchanged from the proof record.

  • Verification does not require an account.
  • If one byte changed, the fingerprints will not match.
  • Once the blockchain layer is added, this same check will compare against the on-chain hash.
