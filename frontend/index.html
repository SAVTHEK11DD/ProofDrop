THE PROCESS

Three steps, in order, because each one depends on the last.

For this local v1 pass, sealing means hashing the file and saving a portable proof record. The blockchain step comes next.

STEP 01 / DROP

Drop the file

Your file is fingerprinted right in the browser using a one-way hash. The file itself is never uploaded or stored anywhere.

STEP 02 / SAVE

Download the proof

The generated proof record stores the filename, size, hash, timestamp, and local preview anchor.

STEP 03 / VERIFY

Verify, anytime

Anyone with the file and proof record can recompute the fingerprint locally and confirm whether the bytes still match.

WHY IT HOLDS UP

Verification that starts with the file itself

  • 01

    The file never leaves your device

    Hashing happens locally, so there is nothing sensitive for anyone to intercept or store.

  • 02

    The fingerprint is deterministic

    The same file produces the same SHA-256 hash. Change one byte and the fingerprint changes.

  • 03

    The proof record is portable

    Download it and store it next to the original. The verify page can check it without a server.
